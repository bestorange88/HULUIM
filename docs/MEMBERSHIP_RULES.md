# 会员等级规则

## 概述

本文档描述了Alo生态应用中会员等级系统的规则和逻辑。

## 会员等级结构

会员等级存储在 `membership_tiers` 表中，包含以下关键字段：

- `id`: 等级唯一标识
- `name`: 等级名称（如：普通会员、钻石会员、至尊会员）
- `price`: 等级基础售价（一次性价格）
- `sort_order`: 等级排序（数值越大等级越高）
- `is_active`: 是否启用

## 补差价升级规则

### 核心逻辑

系统根据各等级的 `price` 字段自动计算补差价金额：

```
新等级售价 - 当前等级售价 = 用户需支付的升级金额
```

### 规则说明

1. **首次购买**：用户首次购买会员时，支付目标等级的完整价格。

2. **升级购买**：用户已有会员等级时，购买更高等级只需支付差价。
   - 例如：用户当前是钻石会员（¥100），升级到至尊会员（¥300），只需支付 ¥200。

3. **不允许降级**：系统不允许用户购买价格低于或等于当前等级的会员。
   - 如果目标等级价格 ≤ 当前等级价格，系统会提示您当前已是该等级或更高等级，无需重复购买。

4. **等级判定**：系统根据 `sort_order` 字段判断等级高低，而非价格。
   - 这确保了即使两个等级价格相同，也能正确判断等级关系。

5. **多等级处理**：如果用户拥有多个会员等级，系统以最高等级（`sort_order` 最大）为基准计算差价。

### 技术实现

升级价格计算通过 Edge Function `calculate-membership-upgrade` 实现：

```typescript
// 请求参数
{
  targetTierId: string  // 目标会员等级ID
}

// 返回结果
{
  currentTierId: string | null,    // 当前等级ID
  currentTierName: string | null,  // 当前等级名称
  currentPrice: number,            // 当前等级价格
  targetTierId: string,            // 目标等级ID
  targetTierName: string,          // 目标等级名称
  targetPrice: number,             // 目标等级价格
  payableAmount: number,           // 需支付金额
  isUpgrade: boolean,              // 是否允许升级
  message: string                  // 提示信息
}
```

### 前端展示

会员中心页面根据用户状态显示不同信息：

- **未购买会员**：显示原价 ¥xxx + 立即开通
- **已有低级别会员**：显示升级只需补差价 ¥yyy
- **已是该等级或更高**：禁用购买按钮，提示无需重复购买

### 后台配置

管理后台的会员等级配置页面中：

1. 确保每个等级都设置了正确的 `price`（基础售价）
2. 确保 `sort_order` 正确反映等级高低关系
3. 系统会自动根据这些配置计算补差价金额

## 注意事项

- 修改等级价格后，已购买用户的等级不受影响
- 新的差价计算会立即生效，影响后续的升级购买
- 建议在修改价格前通知用户，避免产生误解
